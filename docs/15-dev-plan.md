# 15. 개발 계획

> 상태: 초안
> 기준: 주 18시간 (평일 + 주말). **날짜에 맞추지 않고 마일스톤의 완료 기준으로 진행한다**
> 근거 문서: 06 V0 기능, 09 화면 목록, 10 DB 구조, 12 박사 설계, 14 지식 계획

---

## 원칙

- **마감이 아니라 완료 기준으로 진행한다.** 마일스톤의 완료 기준을 모두 만족하면 다음으로
- **얇게 한 줄로 먼저 잇는다.** 화면 하나를 완벽하게 하기보다 로그인 → 등록 → 기록 → 박사가 먼저 이어지게
- **안전이 먼저.** 위험 신호 흐름과 기록 시점 검사 규칙을 LLM 대화보다 먼저 완성
- **콘텐츠는 병행.** 매주 시간의 일부를 콘텐츠 작업에
- **매주 돌아가는 상태 유지.** 주가 끝날 때 앱이 실행되는 상태로 마무리
- **알파는 V0 전체가 완성되면 한 번에 배포**

---

## 마일스톤

| #   | 마일스톤          | 완료되면 할 수 있는 것                       | 참고 시간 |
| --- | ----------------- | -------------------------------------------- | --------- |
| M1  | 기반              | 로그인해서 빈 홈을 봄                        | 약 15h    |
| M2  | 첫 흐름           | 콩이를 등록하고 홈에서 봄                    | 약 18h    |
| M3  | 기록              | 텍스트·음성으로 기록하면 박사가 한두 줄 반응 | 약 40h    |
| M4  | 박사              | 위험 신호 확인이 항상 동작, 박사와 자유 대화 | 약 35h    |
| M5  | 약속·미션·알림    | 3일 뒤 박사가 먼저 물어봄                    | 약 25h    |
| M6  | 병원 권고·사진·홈 | V0 기능 전체                                 | 약 30h    |
| M7  | 알파 배포         | 테스터가 사용 시작                           | 약 15h    |

- 개발 약 180시간 + 콘텐츠 약 35시간 = 약 215시간
- 주 18시간 기준 **대략 12~14주** (참고값. 실제 속도에 따라 달라짐)

## M1. 기반

**만드는 것**

- Expo 프로젝트, **개발 빌드**(Expo Go로는 푸시 테스트 불가), 내비게이션 구조 (탭: 홈 · 기록 · 박사 · 가이드)
- 로컬 Supabase(Docker) 실행, 클라우드 개발용 프로젝트 생성
- 이메일 로그인(개발 빌드 전용), 소셜 로그인(애플·구글, 개발용 프로젝트에서 테스트), 앱 실행 이동 규칙의 첫 단계 (로그인 안 됨 → S01)
- DB 적용, 타입 생성, 데이터 캐시 설정
- 디자인 토큰 초안 (간격, 글자 크기, 색 이름)

**완료 기준**

- [ ] 로그인 → 빈 홈 진입
- [ ] 앱을 껐다 켜도 로그인 유지
- [ ] DB 타입이 앱에서 자동완성됨

**개발 환경**

| 환경            | 위치                             | 용도                                                         |
| --------------- | -------------------------------- | ------------------------------------------------------------ |
| 로컬            | 내 컴퓨터 Docker (Supabase 전체) | 대부분의 개발. 이메일 로그인 사용                            |
| 개발용 클라우드 | Supabase 개발용 프로젝트         | 소셜 로그인, 푸시 테스트 (개발 빌드 + 시뮬레이터·에뮬레이터) |
| 알파            | Supabase 프로젝트 (서울)         | 테스터 사용 환경                                             |

- 테스트 기기: iOS 시뮬레이터(Xcode 14+, Apple Silicon Mac), Google Play가 포함된 안드로이드 에뮬레이터
- 세 환경은 같은 마이그레이션으로 맞춤

**함께 할 콘텐츠**: 즉시 병원 신호 목록 초안 (14 최우선)
**미리 할 일**: Apple 개발자 계정 신청 (승인에 시간이 걸릴 수 있음. M5 푸시, M7 배포에 필요)

## M2. 첫 흐름

**만드는 것**

- 박사 인사(S02), 경험 수준 저장
- 입양 전 가이드(S03), 입양 준비 상태 홈
- 개체 등록(S04, 1마리), 분양 정보 → 입양 전 기록
- 기본 홈(S06): 개체 이름, 최근 기록 자리
- 앱 실행 이동 규칙 전체 (08)

**완료 기준**

- [ ] 세 갈래(데려오기 전 / 막 데려옴 / 키워본 적 있음)가 각각 끝까지 이어짐
- [ ] 두 번째 개체 등록이 막힘
- [ ] 앱을 다시 열면 상태에 맞는 화면으로 이동

**속도 점검**: M1~M2 실제 소요 시간으로 이후 참고 시간 조정

## M3. 기록

**만드는 것**

- 텍스트 기록(S07): 먹이(결과, 더스팅), 배변(상태, 이상 소견), 체중, 탈피
- 확인 카드, 기록 목록(S10) 수정·삭제, 개체 정보(S11)
- 기록 시점 검사 규칙 (04 V0 규칙 목록)
- 음성 기록: 녹음 → STT → 구조화 → 확인 카드, 여러 기록 한 번에 저장

**완료 기준**

- [ ] 기록 종류 4가지 모두 저장·수정·삭제
- [ ] 묽은 배변 1회 / 반복 / 이상 소견에 각각 맞는 반응
- [ ] 탈피 "껍질 남음"이면 발가락 확인 질문
- [ ] "귀뚜라미 세 마리 칼슘 묻혀서 줬고 똥도 쌌어"가 기록 2건으로 저장

**함께 할 콘텐츠**: 기록 시점 검사 기준값 (14 확정 필요 수치)

---

## M4. 박사

**만드는 것** (순서대로)

1. 대화 화면(S08): 메시지 타입, 하단 칩, 첫 화면 추천 질문 칩
2. 사전 설계 흐름 실행기, 긴급 점검·거식·위험 신호 흐름
3. 병원 권고 화면(S09): 권고, 진료용 기록 요약(화면), 지도 바로가기
4. 박사 서버 함수: 상황 블록, 하루 예산, 출력 검증, 스트리밍
5. 참고 자료 보기

**완료 기준**

- [ ] 위험 신호 흐름이 LLM 없이 끝까지 동작, 예산을 다 써도 동작
- [ ] 정답지 10개로 평가 통과 기준 만족 (12: 위험 시나리오 100%, 형식 오류·금지 표현 0, 품질 평균 4.0 이상)
- [ ] 예산 소진 시 안내 후 위험 확인으로 연결

**함께 할 콘텐츠**: 사전 설계 흐름 내용, 박사 설명서, 지식 자료(정답지 주제부터), 채팅창에서 정답지로 미리 시험

---

## M5. 약속·미션·알림

**만드는 것**

- 적응 미션(날짜별 항목), 홈 미션 카드
- 박사의 약속 생성, 기록으로 자동 해결 ("먼저 알려줬네!")
- 서버 푸시: 기기 토큰 등록, 알림 권한(약속하는 순간에 요청)
- 발송 스케줄러, 알림 눌러 들어오기 (08 외부 진입)

**완료 기준**

- [ ] 약속 시간이 되면 모든 기기에 알림
- [ ] 알림 전에 기록하면 알림이 오지 않음
- [ ] 개체 보관 시 약속·미션 종료, 알림 없음
- [ ] 미션 체크 대신 일반 기록으로도 미션 항목 체크

---

## M6. 병원 권고·사진·홈

**만드는 것**

- 진료용 기록 요약 PDF 내보내기·공유
- 기준 사진 촬영(S05): 실루엣 가이드, 압축 업로드
- 홈 완성: 박사 한마디 + 추천 질문 칩, 개체 요약 숫자(마지막 급여·체중 변화·마지막 탈피), 다음 체크
- 설정(S13): 경험 수준, 알림 시간, 계정 삭제

**완료 기준**

- [ ] PDF를 메신저로 공유 가능
- [ ] 홈이 적응기 / 평소 / 입양 준비 세 상태로 바뀜
- [ ] 계정 삭제 시 사진 파일까지 삭제
- [ ] 06 Must 전체 동작
