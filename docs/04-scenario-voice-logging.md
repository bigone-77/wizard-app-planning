# 04. 상세 시나리오 #2: 퇴근 후 음성 기록

> 상태: 초안 확정 (2026-10-06)
> 페르소나: A 신태일 (입양 3주 차)

---

## 상황 설정

- 입양 3주 차. 적응 미션 이후 콩이가 잘 먹기 시작함
- 태일은 매일 앱을 열지는 않음. 먹이 준 날 정도만 기록
- 평일 저녁 8시, 퇴근 후 사육장 앞. 한 손에 핀셋, 다른 손에 휴대폰

---

## 흐름

### ① 먹이를 주고 나서

귀뚜라미 세 마리를 줬고, 배변도 했는데 좀 묽어 보인다.

### ② 음성 입력

> "오늘 귀뚜라미 세 마리 먹였고 똥도 쌌어. 근데 좀 묽었어."

- 한 문장에 기록 2개(먹이, 배변) + 관찰 1개(묽음)
- 입력 시작 방식(버튼 형태·위치)은 **화면 설계 단계에서 결정**
- 시나리오 요구사항: 한 손으로 빠르게 음성 입력 시작 가능, 말한 내용은 항상 박사가 받음

### ③ 구조화 + 확인 카드

```text
🧑‍🔬 "이렇게 기록할게, 맞아?"

🍖 먹이   귀뚜라미 3마리 · 먹음
💩 배변   있음 · 상태: 묽음
🕗 시간   오늘 저녁 8시

[저장]  [수정]
```

### ④ 저장 → 기록 시점 검사

배변 기록 저장 시 최근 배변 기록 3개를 조회해 규칙 확인. 오늘 묽음 1회 → 1단계.

### ⑤ 박사의 반응 (1단계)

> 🧑‍🔬 "저장했어! 잘 먹었네 👍 배변이 한 번 묽은 건 괜찮을 때가 많아. 다음에 배변 기록하면 내가 같이 봐줄게."

평소 기록에 대한 박사의 반응은 **한두 줄**. 길어지면 기록이 귀찮아진다.

### ⑥ 다음 배변 기록 시

- **정상** → "이번엔 괜찮네! 지난번엔 일시적이었나 봐."
- **또 묽음 (2단계)** → "최근에 두 번 연속 묽었네. 몇 개만 확인해볼까?" [지금 확인하기] [나중에]
- **3단계** → 선택지 없이 병원 상담 권고

### ⑦ 남는 기록

먹이 기록, 배변 기록, STT 원문. 별도의 "세션 기억"이나 예약은 없음.

---

## 핵심 설계: 기록 시점 검사

빨간불마다 상황을 기억하고 트리거를 예약하지 않는다.
→ 신호가 불규칙하게 쌓이면 예약이 겹치고, 유효성 관리가 필요하고, 알림 타이밍이 꼬인다.

대신 **기록이 저장될 때마다 최근 기록을 다시 본다.** DB에 쌓인 기록 자체가 기억이다.

```text
배변 기록 저장됨
   ↓
최근 배변 기록 3개 조회
   ↓
1단계: 묽음 1회         → 기록 + 가볍게 한마디
2단계: 묽음 2회         → 확인 제안 [지금 확인하기] [나중에]
3단계: 묽음 3회 이상, 또는 거식·체중 감소 동반 → 병원 상담 권고 (선택지 없음)
```

- 사용자가 기록하는 순간 = 사육장 앞 = 박사가 말 걸기 가장 자연스러운 때
- 구현: 기록 저장 후 Edge Function에서 최근 기록 쿼리 + 규칙 판정

### 규칙 예시 (V0 후보, 수치는 RAG 자료 검토 후 확정)

| 규칙           | 조건                                            |
| -------------- | ----------------------------------------------- |
| 묽은 배변 반복 | 최근 배변 3회 중 묽음 2회 이상                  |
| 급여 거부 지속 | 급여 거부 연속 N회 (입양 초기는 기준 완화)      |
| 체중 감소      | 기준 대비 일정 비율 이상 감소                   |
| 복합 신호      | 묽은 배변 + 거식, 또는 + 체중 감소 → 바로 3단계 |

## 시간 기준 알림과의 역할 분리

| 장치                     | 언제                                      | 방식                                               |
| ------------------------ | ----------------------------------------- | -------------------------------------------------- |
| 기록 시점 검사           | 기록이 저장될 때마다                      | 최근 기록을 규칙으로 확인. 예약 없음               |
| 박사의 약속 (follow_ups) | 상담 끝에 박사가 명시적으로 약속했을 때만 | **개체당 진행 중 1개**. 새 약속은 기존 약속을 대체 |

## 도출된 요구사항

| 영역       | 요구사항                                     |
| ---------- | -------------------------------------------- |
| STT 구조화 | 한 문장에서 여러 기록 동시 추출              |
| STT 구조화 | 시간 미언급 시 현재 시각 기본값              |
| STT 구조화 | 저장 전 확인 카드 + 수정 (오인식 대비)       |
| 기록       | STT 원문(raw_text) 함께 저장                 |
| 박사 반응  | 평소 기록엔 한두 줄로 짧게                   |
| 이상 감지  | 기록 시점 검사 (규칙 기반, 단계별 대응)      |
| 이상 감지  | 2단계는 사용자에게 선택권, 3단계는 즉시 권고 |
| 후속 알림  | 박사의 명시적 약속에만, 개체당 1개           |
