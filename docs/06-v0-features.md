## 병원 권고 방식 (01의 V0 결정 변경)

### 변경 이유

- 지도 API로 "파충류 진료 가능 병원"을 필터링하면 정보가 불확실하거나 거의 없음
- 앱 안에 병원 목록을 띄우면 그 정확성에 대한 책임이 앱으로 넘어옴
- 감당하려면 자체 검증 목록 관리 필요 → V0 규모를 넘음 (배보다 배꼽)

### 바뀐 방향: 병원을 찾아주는 대신, 병원에 가는 걸 돕는다

**1. 진료용 기록 요약**
박사가 병원을 권고할 때 그동안의 기록을 수의사에게 보여줄 한 장으로 정리.

```text
콩이 · 펫테일 게코 · 아성체 · 분양 2026-10-02

- 분양 4일째부터 급여 거부 (시도 3회 / 섭취 0회)
- 최근 배변 3회 중 2회 묽음
- 체중 기록 없음
- 사육 온도: 바닥 "따뜻함" (수치 미확인)
- 외관: 사용자 응답 기준 이상 없음
```

- 초보는 병원에서 경과와 사육 환경을 설명하기 어려움
- 이미 쌓인 기록을 쓰므로 추가 데이터 관리 없음
- **이 앱만 할 수 있는 일**

**2. 외부 지도 검색 바로가기**

- 버튼을 누르면 카카오맵/네이버 지도 앱이 "특수동물병원" 검색어로 열림 (앱 미설치 시 웹 지도 검색)
- 앱은 필터링·검증을 하지 않고 지름길만 제공 → 관리 부담 없음
- 박사: "가기 전에 꼭 전화로 파충류 진료 되는지 확인해!"

## 가게 제휴 메모 (Later)

가게는 **입양이 일어나는 장소**라 이 앱과 궁합이 좋은 파트너.

| 경로                    | 효과                                               |
| ----------------------- | -------------------------------------------------- |
| 인스타 정적 콘텐츠 → 앱 | 1A 준비형 사용자 유입                              |
| 분양 시 QR 카드         | 1B 사용자 유입                                     |
| 분양 정보 사전 입력     | 등록 부담 감소, 박사가 처음부터 정확한 데이터 확보 |

주의:

- **박사의 중립성 유지.** 박사 답변에 특정 가게 상품 추천 X. 가게 콘텐츠는 "파트너 콘텐츠"로 표시해 별도 영역에
- **지식 자료 편입은 별개.** 사용 허락 + 정확성 검토 필요

V0에서 미리 할 일: 입양 전 콘텐츠와 분양 정보를 지금처럼 **구조화된 형태로** 만들어두기 → 나중에 연동해도 구조 변경 없음.
