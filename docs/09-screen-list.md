### 홈(S06) 구성

위에서부터:

| 영역        | 내용                                                                            | 데이터 출처                 |
| ----------- | ------------------------------------------------------------------------------- | --------------------------- |
| 상단        | 개체 이름 · 설정                                                                | `pets`                      |
| 박사 한마디 | 지금 상황에 맞는 한두 문장 + **추천 질문 칩 2개** (누르면 그 질문으로 S08 시작) | 기록·약속·미션으로 생성     |
| 상황 카드   | 적응기: **적응 미션** / 평소: **최근 기록** 3건                                 | `missions` / `care_records` |
| 개체 요약   | 사진, 종·크기, 우리 집에 온 지 N일, **마지막 급여 · 체중과 변화 · 마지막 탈피** | `pets`, `care_records`      |
| 다음 체크   | 박사의 약속·미션이 있으면 그것, 없으면 가벼운 제안 한 줄                        | `follow_ups`, `missions`    |
| 하단        | 기록하기(음성) 버튼, 탭 (홈 · 기록 · 박사 · 가이드)                             |                             |

**입양 준비 상태** (개체 없음): 박사 한마디 + 입양 전 가이드 진행 상황 + [데려왔어!] 버튼

**넣지 않는 것**: 할 일 개수, 빨간 "기한 지남" 배지, 연속 기록 (11: "매일 강요하지 않는다")

**체중 감소 표시**: 줄어든 숫자만 덩그러니 보여주지 않고, 의미 있는 감소면 박사 한마디로 설명

### 박사 대화(S08) 첫 화면

- 대화가 비어 있을 때 **추천 질문 칩**을 보여줌 (예: "안 먹으면 어떡해?", "칼슘 얼마나 줘?") — 상황별로 다르게
- 입력창 문구: **"콩이에 대해 물어봐"** (개체 이름)
- 박사 하루 예산을 다 쓴 경우: "오늘 자세한 이야기는 여기까지지만, 위험한 신호인지는 지금 같이 확인해볼게" → 사전 설계 위험 신호 흐름은 계속 사용 가능

## 질문 흐름은 별도 화면이 아니라 박사 대화(S08) 안에

- 박사가 말풍선으로 질문하고, 선택지는 버튼으로 표시
- 박사가 질문하는 장면은 처음부터 "대화"였으므로 가장 자연스러움
- 화면 수 감소
- **1B 긴급 환경 점검 = 박사와의 첫 대화.** S02에서 "막 데려왔어" → 바로 S08에서 박사가 점검 시작
  → 앱의 첫인상이 "설문 앱"이 아니라 "박사가 나를 챙긴다"

### 화면 배치: 하단 빠른 답장 칩

| 방식                        | 장점                                            | 단점                                                                 | 레퍼런스         |
| --------------------------- | ----------------------------------------------- | -------------------------------------------------------------------- | ---------------- |
| A. 말풍선 안 버튼           | 질문과 선택지가 한 덩어리                       | 답한 질문의 버튼이 남아 지저분, 버튼이 화면 위쪽이라 한 손 조작 불편 | 카카오톡 챗봇    |
| **B. 하단 빠른 답장 칩** ✅ | 엄지 위치, 지금 질문에만 집중, 대화 기록이 깔끔 | 질문과 선택지가 시각적으로 떨어짐                                    | Ada Health, Wysa |

B의 동작:

1. 박사 질문은 말풍선으로
2. 선택지는 **입력창 바로 위에 칩**으로
3. 칩을 누르면 칩은 사라지고 **선택한 답이 사용자 말풍선**으로 올라감 (사용자 메시지 `payload`: `{ "answer_to": <질문 id>, "option_id": "ok" }`)
4. 입력창 문구는 "직접 입력할게" → 버튼으로 표현하기 애매한 답은 말로 (LLM이 처리)

### 배치 규칙

> **답하고 지나가는 질문은 하단 칩, 남아야 하는 결과는 대화 속 카드.**

| 대화 속 카드로 남기는 것 | 이유                      |
| ------------------------ | ------------------------- |
| 병원 권고 카드 (→ S09)   | 나중에 다시 열어봐야 함   |
| 미션 생성 카드           | 무엇을 하기로 했는지 기록 |
| 기록 확인 카드           | 무엇이 저장됐는지 기록    |

### 레퍼런스 앱

- **카카오톡 챗봇**: 한국 사용자에게 가장 익숙한 버튼형 대화
- **Ada Health**: 위험 신호를 거르는 증상 질문 흐름, 진단이 아닌 다음 행동으로 끝남 → 박사 상담과 가장 유사
- **Lemonade**: 가입 양식을 캐릭터(Maya)와의 대화로 → 긴급 점검을 박사와의 첫 대화로 만드는 방향
- **Wysa**: 친근한 캐릭터가 선택지를 섞어 대화하는 톤

## 구현 메모

### 1. 메시지를 타입으로 정의

```ts
type ChatMessage =
  | { id: string; role: "doctor" | "user"; type: "text"; text: string }
  | {
      id: string;
      role: "doctor";
      type: "choice";
      text: string;
      options: { id: string; label: string }[];
    }
  // 답변 여부는 박사 메시지를 수정하지 않고, 이 메시지를 가리키는 사용자 메시지로 판단 (10 참고)
  | { id: string; role: "doctor"; type: "hospital"; summaryId: string }
  | { id: string; role: "doctor"; type: "mission"; missionId: string }
  | { id: string; role: "doctor"; type: "log_confirm"; logIds: string[] };
```

### 2. 화면은 타입별로 그리기만

```tsx
function MessageItem({ msg }) {
  switch (msg.type) {
    case "text":
      return <Bubble role={msg.role} text={msg.text} />;
    case "choice":
      return <Bubble role="doctor" text={msg.text} />; // 선택지는 하단 칩 영역에서 렌더
    case "hospital":
      return <HospitalCard summaryId={msg.summaryId} />;
    case "mission":
      return <MissionCard missionId={msg.missionId} />;
    case "log_confirm":
      return <LogConfirmCard logIds={msg.logIds} />;
  }
}
```

- 채팅 목록: `FlatList`
- 하단 칩 영역: 마지막 메시지가 `choice`이고 이를 `answer_to`로 가리키는 사용자 메시지가 없으면 그 `options`를 칩으로 렌더

### 3. 다음 질문의 두 가지 출처 — 같은 형식

**사전 설계 흐름** (긴급 환경 점검, 거식 등): JSON 정의

```json
{
  "id": "q1_condition",
  "text": "콩이 몸 상태는 어때 보여?",
  "options": [
    { "id": "ok", "label": "멀쩡해 보여", "next": "q2_temp" },
    { "id": "unsure", "label": "잘 모르겠어", "next": "q1_sub_checks" },
    { "id": "bad", "label": "좀 이상해", "next": "RED_FLAG" }
  ]
}
```

**LLM 생성 질문**: Edge Function에서 구조화 출력으로 **같은 형식**의 메시지 생성

- 화면 코드는 질문의 출처를 신경 쓰지 않음 → 사전 설계로 시작해 점차 LLM 비중을 늘려도 UI 변경 없음
- **안전 보장**: 사전 설계 흐름의 위험 선택지는 `RED_FLAG`로 고정 → LLM 판단과 무관하게 위험 신호 확인으로 이동
  ("위험 신호는 LLM에만 맡기지 않는다"가 코드 구조로 보장됨)

### 4. 저장

```text
ai_messages
  conversation_id, role, type, payload: jsonb, created_at
```

- `payload`에 타입별 데이터(질문, 선택지, 선택한 답 등) → 대화를 다시 열어도 상태 복원
- 선택한 답은 환경 기록·건강 체크 등 **실제 기록으로도 함께 저장**
