# 02. 개체 등록 요구사항

> 상태: 초안 확정 (2026-10-06)
> DB 스키마는 "DB 구조" 단계에서 최종 정리. 아래 스키마는 방향 메모.

---

## 원칙

1. **첫 등록은 최소한만 받는다.** 1B 충동형 사용자는 긴 폼에서 이탈한다.
2. **나머지는 박사가 대화하며 점진적으로 채운다.** ("참, 혹시 성별은 알아?")
   → 등록 단계부터 박사가 UX의 중심이 되도록.
3. **구조화할 수 있는 정보는 자유 문장으로 받지 않는다.** 선택지·날짜 선택기 사용.
   음성 입력 시: STT → LLM 구조화 → 확인 카드 → 저장.
4. **자유 입력은 원문(`raw_text`)도 함께 저장한다.** 스키마/추출 로직 변경 시 재변환 가능.
5. **"모름"을 항상 허용한다.** 모름 = null. 가짜 값보다 빈 값이 나음.

---

## 등록 항목

### 첫 등록 (필수)

| 항목      | 입력 방식               | 비고                                                                |
| --------- | ----------------------- | ------------------------------------------------------------------- |
| 종        | 선택                    | MVP는 펫테일 게코                                                   |
| 이름      | 텍스트                  |                                                                     |
| 분양일    | 날짜 선택               | 적응 기간 판단 기준                                                 |
| 나이      | 생년월일 또는 크기 단계 | 모르면 해츨링 / 아성체 / 성체 선택. 급여 주기·성장 기준 판단에 사용 |
| 기준 사진 | 촬영                    | 아래 "기준 사진" 참고                                               |

### 첫 등록 (선택)

| 항목 | 비고                                                                           |
| ---- | ------------------------------------------------------------------------------ |
| 체중 | **필수 아님.** 자취생 등 저울이 없는 사용자 고려. 입력 시 첫 weight_log로 저장 |

### 박사가 이후 점진적으로 수집

| 항목              | 이유                                        | 저장 방식          |
| ----------------- | ------------------------------------------- | ------------------ |
| 성별 (수/암/모름) | 암컷은 무정란 산란·알막힘 리스크            | pets 컬럼 (enum)   |
| 분양 시 정보      | 입양 직후 "안 먹는데 괜찮나?" 판단          | 아래 참고          |
| 특이사항          | 재생 꼬리 등 사진 분석 오판 방지            | 별도 테이블        |
| 모프              | 외형 판단(알비노 눈 색 등), 숙련자의 정체성 | 종별 선택지 + 배열 |
| 성격/핸들링 반응  | 정서적 가치                                 | text 컬럼          |

## 체중이 없을 때

- **꼬리 사진을 기준선으로 사용.** 펫테일은 꼬리에 지방을 저장 → 꼬리 굵기가 영양 상태 지표
- **분양처에서 체중을 받아오도록** 분양 시 질문 리스트에 포함
- **0.1g 단위 소형 전자저울**을 준비물 체크리스트에서 "있으면 좋은 것"으로 안내 (강요 X)
- 박사는 체중 기록이 없으면 **판단 근거의 한계를 솔직하게 말한다**
  ("체중 기록이 없어서 정확도가 조금 떨어질 수 있어")

## 분양 시 정보 → 기존 기록 테이블에 "입양 전 기록"으로 저장

분양 정보는 대부분 이벤트다. pets에 컬럼을 늘리지 않고 로그 테이블에 출처를 표시해 넣는다.
→ 박사가 입양 전/후 기록을 같은 방식으로 조회 가능.

| 분양 정보      | 저장 위치                                        |
| -------------- | ------------------------------------------------ |
| 마지막 급여일  | feeding_logs 1건 (`source = 'adoption_info'`)    |
| 최근 탈피일    | shed_logs 1건 (`source = 'adoption_info'`)       |
| 먹던 먹이 종류 | pets.main_feeder_type                            |
| 분양처         | pets.adoption_source_type / adoption_source_name |
| 분양 시 체중   | weight_logs 1건 (`source = 'adoption_info'`)     |

```text
feeding_logs
  pet_id, fed_at, feeder_type, quantity
  result: 'eaten' | 'refused' | 'partial' | 'unknown'   ← 03 시나리오에서 추가
  source: 'adoption_info' | 'user' | 'stt'

shed_logs          ← 기존 스키마(문서 11번)에 없음. 추가 필요
  pet_id, shed_at, status, source

pets
  adoption_source_type: 'shop' | 'breeder' | 'individual' | 'other'
  adoption_source_name: text (nullable)
  main_feeder_type: enum (귀뚜라미, 밀웜, 듀비아, 기타 …)
  sex: 'male' | 'female' | 'unknown'
  morphs: text[]
  personality: text
```

## 특이사항 → 별도 테이블 (1:N)

박사와 사진 분석이 **확실히 알아야 하는 사실**이므로 문장 속에 묻지 않고 카테고리로 저장.

```text
pet_conditions
  pet_id
  category: 'tail_regenerated' | 'toe_missing' | 'eye' | 'scar' | 'other'
  body_part: 'head' | 'body' | 'tail' | 'leg' | ...
  note: text           ← 사용자 자유 설명
  since: date (nullable)
  photo_id (nullable)
```

## 기준 사진

### 촬영 가이드 (1차 방어)

- 촬영 화면에 도마뱀 실루엣 가이드 프레임
- 안내 문구: "머리부터 꼬리 끝까지, 위에서 찍어주세요"
- **위에서 찍기**: 이후 꼬리 굵기 비교 시 각도 일관성 확보

### AI 검증 (2차)

- Vision 모델에 구조화된 결과 요청: `{ head, body, tail, blurry }`
- **실패해도 저장을 막지 않는다.**
  "꼬리가 잘 안 보여요, 다시 찍을까요?" + [다시 찍기] [그냥 저장]
  → 도마뱀은 가만히 있지 않음. 막으면 이탈.

### 저장

- 파일: Supabase Storage (S3 호환, 스택 통일)
- 메타데이터: photos 테이블

```text
photos
  pet_id, storage_path, taken_at
  photo_type: 'baseline_full' | 'tail' | 'defecation' | 'general'
  validation: jsonb    ← { head, body, tail, blurry }
  is_baseline: boolean
```

## 별도 검토 항목

- **사육장 정보**(크기, 바닥재, 온열 장치)는 개체 정보와 분리된 "사육장" 항목으로.
  예: 바닥재가 모래면 섭취로 인한 장 막힘 위험을 먼저 의심 → 박사 답변에 영향
- 등록 시점에 받을지, 박사가 이후에 물어볼지 결정 필요
