# 03. 상세 시나리오 #1: 입양 4일째 거식

> 상태: 초안 확정 (2026-10-06)
> 페르소나: A 신태일 (1B 충동형) / 평가: B 숙련자 친구

---

## 상황 설정

- 4일 전 샵에서 펫테일 게코 아성체 분양 (이름: 콩이)
- 등록 시 필수 항목만 입력: 종, 이름, 분양일, 크기(아성체), 기준 사진
- 체중 없음, 분양 전 마지막 급여일 "모름"
- 입양 후 2일차, 4일차 두 번 귀뚜라미 급여 → 둘 다 거부

> 데이터가 거의 없는 상태 = 실제 초보 사용자의 가장 흔한 상태. 박사가 가장 어려운 조건에서 어떻게 움직이는지 검증.

---

## 흐름

### ① 문제 발생 (저녁 9시)

귀뚜라미를 넣었는데 콩이가 쳐다만 보고 숨어버림. 태일이 앱을 열고 음성으로:

> "박사님, 콩이가 오늘도 밥을 안 먹어."

### ② 박사의 내부 조회

분양 4일째 / 아성체 / 분양 전 급여일 모름 / 입양 후 급여 시도 2회 모두 거부 / 체중 없음 / 기준 사진 있음

### ③ 짧은 아키네이터식 확인

> 🧑‍🔬 "입양 초반엔 흔한 일이야, 너무 걱정하지 마. 몇 개만 물어볼게!"

| 질문                                                         | 선택지                                  |
| ------------------------------------------------------------ | --------------------------------------- |
| Q1. 콩이 몸 상태는 어때 보여? (위험 신호 배제, 항상 첫 질문) | [멀쩡해 보여] [잘 모르겠어] [좀 이상해] |
| Q2. 사육장 바닥이 따뜻해?                                    | [따뜻해] [잘 모르겠어] [차가운 편]      |
| Q3. 요즘 자꾸 만지거나 꺼내봤어?                             | [자주] [가끔] [거의 안 만졌어]          |

Q1 분기:

- **멀쩡해 보여** → Q2 진행
- **잘 모르겠어** → "그럼 같이 보자!" 구체적 하위 체크 (눈을 잘 뜨고 있어? 비틀거리지 않아? 꼬리가 처음보다 얇아 보여?) → 그래도 애매하면 사진 요청 → 기준 사진과 비교
- **좀 이상해** → 단호한 박사로 전환, 위험 신호 확인 흐름

### ④ 결론 — "가능성 + 할 일 + 다시 찾아올 기준"

> 🧑‍🔬 "몸 상태도 괜찮고 온도도 문제없어 보여. 적응 중일 가능성이 높아!
>
> 1. 3일 동안은 꺼내거나 만지지 말기
> 2. 먹이는 저녁에 넣어주고, 아침까지 안 먹었으면 남은 귀뚜라미는 빼주기
> 3. 3일 뒤에 내가 다시 물어볼게!
>
> 그 전에라도 축 처지거나, 꼬리가 눈에 띄게 얇아지면 바로 알려줘."

→ "3일 뒤에 내가 먼저 물어봐도 될까?" [좋아] → **이 시점에 알림 권한 요청**

### ⑤ 남는 기록

| 기록      | 내용                                                 |
| --------- | ---------------------------------------------------- |
| 먹이      | 귀뚜라미 급여 → 거부                                 |
| 환경      | 바닥 온도 "따뜻함" (수치 없음, 불확실성 표시)        |
| 건강 체크 | 외관상 이상 없음 (사용자 응답 기준)                  |
| 대화 요약 | 입양 4일차 거식, 적응 스트레스 추정, 3일 비접촉 권고 |
| 후속 약속 | 3일 뒤 먹이 여부 확인                                |

### ⑥ 대기 기간 — 적응 미션

3일은 "기다림"이 아니라 **매일 할 일이 있는 기간**.

```text
🧑‍🔬 "콩이 적응 기간이야. 조금만 같이 기다려보자!"

🦎 콩이 적응 미션  D+4 · 1/3일차

☐ 저녁: 귀뚜라미 넣어주기
☐ 아침: 먹었는지 확인하고 남은 거 빼기
☐ 만지지 않기 (오늘도 참기!)

📖 기다리는 동안 알아두면 좋은 것
   "새로 온 게코는 왜 밥을 안 먹을까?"
```

- 미션 체크 = 먹이 기록 (섭취/거부)
- 읽을거리 = 입문 코스와 연결
- 강요가 아니라 **열었을 때 할 일과 배울 게 있게**

### ⑦ 3일 뒤

> 🔔 "콩이 요즘 밥 먹었어? 🦎"

- **먹었다** → 함께 기뻐하고 기록 ("첫 식사 축하해!")
- **아직 안 먹었다** → 한 단계 상향: 꼬리 사진 → 기준 사진 비교, 체중 측정 권유, 1~2주 이상 지속 시 병원 권고 + 근처 병원 지도

### ⑧ B의 평가

> "어, 맞는 말이네. 귀뚜라미 빼라는 것까지 알려주네?"

→ 박사의 결론이 "괜찮아"에서 끝나지 않고 구체적 사육 지식이 담긴 할 일로 끝나야 B의 신뢰를 얻는다.

## 도출된 요구사항

| 영역      | 요구사항                                                                                 |
| --------- | ---------------------------------------------------------------------------------------- |
| 먹이 기록 | "먹음"뿐 아니라 **"줬는데 안 먹음(거부)"** 기록 가능                                     |
| 박사 질문 | 짧은 아키네이터식: 최대 3~5문항, 첫 질문은 항상 위험 신호 배제                           |
| 박사 질문 | 모든 질문은 긍정 / 모르겠어 / 부정 3단계. "모르겠어"는 하위 체크 또는 사진 요청으로 연결 |
| 박사 질문 | LLM이 다음 질문 + 선택지를 구조화 출력. V0는 거식 등 빈출 상황만 흐름 사전 설계          |
| 박사 결론 | 진단이 아닌 "가능성 + 할 일 + 다시 찾아올 기준"                                          |
| 기록      | 답변의 불확실성까지 저장 ("잘 모르겠어"도 기록)                                          |
| 후속 약속 | 박사의 약속(언제·무엇을·왜)을 저장하는 follow_ups                                        |
| 알림      | V0: 기기 로컬 알림 예약 (expo-notifications). 이후 서버 푸시로 이전                      |
| 알림 권한 | 첫 실행이 아니라 박사가 약속하는 순간에 요청                                             |
| 미션      | 박사 결론을 기간형 미션으로 변환, 홈에 표시. 체크 = 기록                                 |
| 사진      | 하위 체크로 먼저 좁히고, 애매할 때만 사진 요청 (Vision 비용 관리)                        |

## 사진 보관 정책

업로드 전 앱에서 리사이즈·압축 (가로 약 1280px, 화질 약 70% → 장당 200~300KB 수준)

| 사진 종류   | 예시                           | 보관                                                |
| ----------- | ------------------------------ | --------------------------------------------------- |
| 기준 사진   | 등록 시 전신, 주기적 꼬리 사진 | 영구                                                |
| 확인용 사진 | "잘 모르겠어" 사진, 배변 사진  | 분석 결과만 남기고 일정 기간(예: 30일) 뒤 자동 삭제 |
| 사용자 저장 | "이 사진 남겨둘래"             | 보관                                                |

- 박사에게 필요한 건 대부분 사진이 아니라 **분석 결과(텍스트)**
- 저장 비용보다 **Vision 호출 비용**이 더 클 가능성 높음
- 출시 전 Supabase / OpenAI 공식 가격 재확인

```text
missions

```
